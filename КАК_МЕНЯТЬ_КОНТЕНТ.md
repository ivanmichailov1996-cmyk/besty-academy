# Как самостоятельно менять контент Besty Academy

Весь контент сайта — это обычные текстовые файлы на TypeScript в папке
`src/content/`. Не нужно уметь программировать, чтобы в них разобраться: это
просто структурированный текст (что-то вроде очень строгого Word-документа),
где важно не потерять кавычки, запятые и фигурные скобки. Эта инструкция
покажет, как редактировать существующий урок, добавлять новые уроки и целые
разделы — без участия Claude.

Если что-то пойдёт не так — не страшно: ошибку почти всегда покажет команда
`npm run build` (см. раздел «Как проверить, что всё работает» ниже) ещё до
того, как что-то попадёт на реальный сайт.

## Где что лежит

- `src/content/types.ts` — описание «форм» урока и блоков контента. Редактировать
  не нужно, но полезно как справочник (в конце этого файла есть его копия).
- `src/content/lessons/*.ts` — сами уроки, по одному файлу на тему (например,
  `production.ts` — уроки производства, `managers.ts` — обучение менеджеров).
  Один файл может содержать несколько уроков.
- `src/content/sections.ts` — какие уроки в каком разделе сайта показываются
  и в каком порядке. Разделы — это те карточки, что видны на главной странице
  («Модули сервис», «Обучающие карточки» и т.д.).

## Структура одного урока

Урок — это объект с такими полями:

```ts
{
  slug: "my-new-lesson",       // уникальный "адрес" урока для ссылки, только
                                // латинские буквы, цифры и дефисы, без пробелов
  title: "Название урока",     // заголовок, показывается на странице урока
  summary: "Короткое описание, которое видно в списке уроков раздела.",
  ready: true,                 // true = урок готов и виден на сайте
  source: "Имя исходного файла.docx", // необязательно, просто для памяти
  blocks: [
    // содержимое урока — см. виды блоков ниже
  ],
  quiz: [
    // вопросы теста в конце урока — см. ниже, необязательное поле
  ],
}
```

**Про кавычки:** весь текст пишется в двойных кавычках `"..."`. Если в самом
тексте нужна кавычка (например, прямая речь), используйте кавычки-ёлочки
`«...»` — они не конфликтуют с двойными кавычками кода. Если очень нужна
именно двойная кавычка внутри текста, поставьте перед ней обратный слэш:
`\"`.

## Виды блоков (что можно вставить в `blocks`)

Каждый блок — это `{ ... }` с полем `type`. Блоки идут по порядку сверху
вниз, через запятую.

**Заголовок раздела внутри урока:**
```ts
{ type: "heading", text: "Название подраздела" },
```

**Обычный абзац текста:**
```ts
{ type: "paragraph", text: "Текст абзаца." },
```

**Список без нумерации:**
```ts
{ type: "list", items: ["Первый пункт", "Второй пункт", "Третий пункт"] },
```

**Пронумерованные шаги (для инструкций по порядку действий):**
```ts
{ type: "steps", items: ["Сначала сделать это", "Потом это", "И наконец это"] },
```

**Блок готовых фраз (для скриптов общения с гостем):**
```ts
{
  type: "phrases",
  title: "Что сказать гостю", // необязательно
  items: ["Здравствуйте! Рады видеть вас в Besty!", "Хорошего вам отдыха!"],
},
```

**Выделенная плашка-предупреждение/совет:**
```ts
{ type: "callout", tone: "warning", text: "Важно: никогда не делайте вот так." },
```
`tone` может быть `"info"` (жёлтая), `"warning"` (красная) или `"success"`
(зелёная). Если не указать — будет жёлтая.

**Таблица:**
```ts
{
  type: "table",
  headers: ["Ситуация", "Что сказать"],
  rows: [
    ["Гость жалуется на вкус", "«Спасибо за отзыв. Подберём другое или позову менеджера.»"],
    ["Долгая выдача заказа", "«Прошу прощения, уточню статус.»"],
  ],
},
```

**Одна картинка:** файл картинки нужно заранее положить в
`public/images/...` (спросите Claude, если нужна помощь с добавлением файла
картинки в проект).
```ts
{ type: "image", src: "/images/имя-папки/имя-файла.jpg", alt: "Описание картинки", caption: "Подпись под картинкой" },
```

**Сетка из нескольких картинок:**
```ts
{
  type: "imageGrid",
  images: [
    { src: "/images/имя-папки/файл1.jpg", alt: "Описание 1" },
    { src: "/images/имя-папки/файл2.jpg", alt: "Описание 2" },
  ],
},
```

**Видео:** см. отдельный раздел «Как добавить видео к уроку» ниже.
```ts
{ type: "video", src: "/videos/имя-файла.mp4", caption: "Видео: о чём это" },
```

## Вопросы теста (`quiz`)

В конце урока может быть тест — массив вопросов:

```ts
quiz: [
  {
    question: "Текст вопроса?",
    options: ["Вариант А", "Вариант Б (правильный)", "Вариант В", "Вариант Г"],
    correctIndex: 1, // номер правильного варианта, считая с нуля (0 = первый)
  },
],
```

`correctIndex: 1` означает, что правильный ответ — второй в списке (считаем
с нуля: 0, 1, 2, 3).

## Как отредактировать существующий урок

1. Откройте папку `src/content/lessons/` в любом текстовом редакторе (удобнее
   всего — бесплатный [VS Code](https://code.visualstudio.com/)).
2. Найдите нужный файл (или воспользуйтесь поиском по всей папке — Ctrl+Shift+F
   в VS Code — по названию урока или его `slug`).
3. Найдите нужный текст внутри кавычек и измените его. Не трогайте кавычки,
   запятые и фигурные скобки вокруг — только текст внутри них.
4. Сохраните файл и проверьте сборку (см. ниже).

## Как добавить новый урок в существующий раздел

1. Откройте файл, где лежат уроки нужного раздела (например, `production.ts`
   для раздела «Модули производство»).
2. Найдите любой существующий урок и скопируйте его целиком — от открывающей
   `{` до закрывающей `},` (это один объект в массиве).
3. Вставьте копию туда же, в массив (перед закрывающей `];` в конце файла или
   между двумя существующими уроками — не важно, порядок в файле определяет
   порядок на сайте).
4. Измените в копии: `slug` (обязательно новый, уникальный, не как у других
   уроков!), `title`, `summary`, `blocks` и `quiz` на свои.
5. Урок сразу появится на сайте в том разделе, где подключён этот файл — в
   `sections.ts` ничего менять не нужно, если файл уже используется в нужном
   разделе целиком (через `...someFileLessons`).

## Как добавить совершенно новый раздел (модуль)

1. Создайте новый файл в `src/content/lessons/`, например `newModule.ts`, по
   образцу любого существующего файла:
   ```ts
   import type { Lesson } from "../types";

   export const newModuleLessons: Lesson[] = [
     {
       slug: "first-lesson",
       title: "Первый урок нового модуля",
       summary: "Краткое описание.",
       ready: true,
       blocks: [
         { type: "paragraph", text: "Текст урока." },
       ],
       quiz: [],
     },
   ];
   ```
2. Откройте `src/content/sections.ts`:
   - вверху добавьте строку импорта: `import { newModuleLessons } from "./lessons/newModule";`
   - в массиве `sections` добавьте новый объект (можно скопировать любой
     существующий и изменить):
     ```ts
     {
       slug: "new-module",              // адрес раздела в ссылке: /new-module
       title: "Название нового раздела",
       description: "Что это за раздел, одна строка.",
       emoji: "🆕",
       lessons: [...newModuleLessons],
     },
     ```
3. Новый раздел сразу появится карточкой на главной странице.

## Как добавить видео к уроку

1. Положите файл видео в папку `D:\BESTY\Обучение\Видео`.
2. Добавьте в конец `blocks` нужного урока (перед `quiz`) блок:
   ```ts
   { type: "video", src: "/videos/имя-для-сайта.mp4", caption: "Видео: о чём это" },
   ```
   `имя-для-сайта.mp4` — придумайте короткое имя латиницей (например,
   `new-video.mp4`), оно не обязано совпадать с исходным именем файла.
3. Откройте все три файла `ЗАПУСТИТЬ_САЙТ.bat`, `ОБНОВИТЬ_ОТ_CLAUDE.bat` и
   `ОПУБЛИКОВАТЬ_НА_GITHUB.bat` — в них внутри (это закодированный
   PowerShell-скрипт) есть список `$videoMap` с парами «исходное имя файла» →
   «имя для сайта». Такие изменения проще всего попросить внести Claude —
   пришлите исходное имя файла видео и как вы назвали его в блоке `video`.

## Как проверить, что всё работает, перед публикацией

Откройте командную строку (PowerShell) в папке с исходниками (например, в
`besty-academy-github`, которую создал скрипт `ОБНОВИТЬ_ОТ_CLAUDE.bat`)
и выполните:

```
npm install
npm run build
```

- Если нигде не ошиблись — сборка пройдёт успешно и покажет список страниц.
- Если где-то пропущена запятая, кавычка или фигурная скобка — сборка
  остановится и покажет **файл и номер строки**, где искать проблему.

Посмотреть сайт локально с вашими правками, не публикуя его:
```
npm run dev
```
и открыть в браузере `http://localhost:3000`.

## Как опубликовать правки на реальном сайте

Теперь для этого есть два разных файла — важно не перепутать их:

- **`ОБНОВИТЬ_ОТ_CLAUDE.bat`** — используйте, когда хотите получить на сайте
  новую версию кода, которую прислал Claude (например, после того как
  попросили что-то переделать или добавить). Он берёт последний
  `besty-academy.zip`, обновляет им файлы в папке `besty-academy-github` и
  сразу публикует результат на GitHub. Если в папке при этом были ваши
  несохранённые ручные правки — скрипт сначала сам сохранит их отдельным
  коммитом в историю Git (её можно посмотреть командой `git log`), а затем
  уже обновит файлы версией от Claude. То есть правки не пропадут бесследно,
  но в самих файлах на сайте останется версия от Claude — если правки нужно
  оставить, сообщите о них Claude, чтобы он перенёс их в новую версию.

- **`ОПУБЛИКОВАТЬ_НА_GITHUB.bat`** — используйте, когда правите файлы сами,
  прямо внутри уже настроенной папки `besty-academy-github`, и хотите
  выложить именно свои правки. Этот скрипт **никогда не трогает архив от
  Claude** и не заменяет файлы — он только коммитит и отправляет на GitHub
  то, что сейчас лежит в папке.

В обоих случаях изменения появляются на живом сайте через 1–2 минуты после
успешной отправки.

**Если не уверены, какой файл запустить** — простое правило: получили новый
архив/ответ от Claude → `ОБНОВИТЬ_ОТ_CLAUDE.bat`; правили сами → `ОПУБЛИКОВАТЬ_НА_GITHUB.bat`.

## Частые ошибки

- **`slug` повторяется** — у каждого урока и каждого раздела должен быть свой
  уникальный `slug`, иначе один урок «перезапишет» другой в ссылках.
- **`slug` с пробелами или кириллицей** — только латинские буквы, цифры и
  дефисы (`my-lesson-2`, не `Мой урок 2`).
- **Забытая запятая** — после каждого блока в `blocks` и после каждого поля
  урока (кроме самого последнего) должна быть запятая.
- **Незакрытая кавычка или скобка** — `npm run build` покажет точное место
  ошибки, ищите его по номеру строки.
- **Двойная кавычка внутри текста в двойных кавычках** — используйте «ёлочки»
  для цитат внутри текста вместо обычных кавычек.

## Справочник: типы данных (для интересующихся)

Это содержимое файла `src/content/types.ts` — точное описание того, какие
поля допустимы у урока и у каждого блока:

```ts
export type ContentBlock =
  | { type: "heading"; text: string }
  | { type: "paragraph"; text: string }
  | { type: "list"; items: string[] }
  | { type: "steps"; items: string[] }
  | { type: "phrases"; title?: string; items: string[] }
  | { type: "callout"; tone?: "info" | "warning" | "success"; text: string }
  | { type: "table"; headers: string[]; rows: string[][] }
  | { type: "image"; src: string; alt: string; caption?: string }
  | { type: "imageGrid"; images: { src: string; alt: string; caption?: string }[] }
  | { type: "diagram"; name: string; caption?: string }
  | { type: "video"; src: string; caption?: string; poster?: string };

export type QuizQuestion = {
  question: string;
  options: string[];
  correctIndex: number;
};

export type Lesson = {
  slug: string;
  title: string;
  summary: string;
  ready: boolean;
  source?: string;
  blocks?: ContentBlock[];
  quiz?: QuizQuestion[];
};

export type Section = {
  slug: string;
  title: string;
  description: string;
  emoji: string;
  lessons: Lesson[];
};
```

Поле с вопросительным знаком (например, `title?`) необязательно — его можно
не указывать вовсе.
